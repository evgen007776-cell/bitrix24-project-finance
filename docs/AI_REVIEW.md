# AI-assisted development review

Тестовое задание намеренно выполнено с ИИ-инструментами, но результат проверялся как обычный production-код, а не принимался «как сгенерировалось».

## Что делегировалось ИИ

- декомпозиция требований в сущности и REST endpoints;
- стартовая структура backend/frontend;
- черновой UI;
- идеи edge cases для финансовых расчётов;
- первичное code review.

## Что проверялось отдельно

- формула прибыли и рентабельности;
- деление на ноль при отсутствии дохода;
- запрет нулевых/отрицательных сумм;
- серверная валидация даты и ссылочных id;
- совместное хранение данных на backend, а не в `localStorage`;
- добавление нескольких сотрудников к одному проекту;
- добавление пользовательских статей доходов и расходов;
- возможность запуска без реального портала Bitrix24;
- поведение при недоступном Bitrix24 JS SDK.

## Ошибка, найденная при проверке результата ИИ

В первой версии агрегирующего SQL-запроса одновременно соединялись таблицы `transactions` и `project_members`. При проекте с несколькими сотрудниками это могло умножить каждую финансовую операцию на количество участников проекта.

Исправление: финансовые операции и команда проекта агрегируются в двух независимых подзапросах, после чего присоединяются к `projects` уже в агрегированном виде.

На этот сценарий добавлен автоматический тест:

`adding multiple project members does not duplicate financial totals`.

Это принципиальная часть подхода к ИИ: генерация ускоряет работу, но финансовая логика должна подтверждаться тестами и ручным ревью.

## Осознанные упрощения тестового задания

Для минимального запуска нет обязательного OAuth Bitrix24: приложение работает standalone и при встраивании пытается получить текущего пользователя через официальный JS SDK. Для production я бы добавил серверную OAuth-проверку, роли доступа и синхронизацию сотрудников из Bitrix24.

SQLite выбран для тестового задания как самый простой общий server-side storage. Для небольшого внутреннего приложения его достаточно; при росте нагрузки миграция на PostgreSQL не меняет frontend и контракт REST API.
