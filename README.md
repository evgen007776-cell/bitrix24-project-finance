# Project Finance for Bitrix24

Веб-приложение для совместного ручного учёта экономики проектов внутри Битрикс24: сделки, выполненные работы, поступления, расходы, прибыль, рентабельность и дебиторская задолженность.

Приложение можно запустить как standalone-сервис для проверки задания или встроить в Битрикс24 через iframe приложения.

## Что реализовано

### Экономика проектов
- проекты с клиентом, менеджером, датой и суммой сделки;
- фиксация выполненных работ отдельной сущностью;
- поступления денег от одного или нескольких плательщиков;
- расходы по системным и пользовательским статьям;
- прибыль и рентабельность;
- накопительная дебиторская задолженность;
- независимые операционный и финансовый статусы проекта;
- фильтрация по периоду, проекту, клиенту, менеджеру, состоянию, движению и минимальной рентабельности;
- табличный и карточный режимы;
- drill-down от KPI до конкретных операций.

### Статьи
Системно создаются:
- `Оплата от клиента`;
- `Внешние программисты`;
- `Внутренние программисты`;
- `Расходы на ИИ`;
- `Аренда сервера`;
- `Дивиденды`.

Можно вручную добавлять новые статьи.

Для расходной статьи можно выбрать модель:
- внешний контрагент;
- сотрудник определённой роли.

При вводе операции employee-linked статья показывает только сотрудников нужной роли.

### Сотрудники и команды
- справочник сотрудников;
- роль сотрудника;
- Bitrix24 user ID;
- назначение менеджера проекта;
- добавление сотрудников в команду проекта;
- аналитика менеджера по управляемому портфелю;
- аналитика участника по проектам участия и персональным расходам.

### Операции и документы
- журнал поступлений и расходов;
- конкретный плательщик / контрагент;
- привязка внутренних расходов к сотруднику;
- комментарии и даты;
- фильтрация по периоду и другим параметрам;
- документы проекта с источником и статусом синхронизации.

## Финансовая модель

Приложение намеренно разделяет договорную стоимость, выполнение и движение денег.

```text
Сумма сделки = договорная стоимость проекта

Выполнено = стоимость фактически закрытых / принятых работ

Получено = фактические денежные поступления от клиента

Расходы = расходы проекта

Прибыль = Выполнено − Расходы

Рентабельность = Прибыль / Выполнено × 100%

Общая дебиторка =
max(0, Выполнено накопительно − Получено накопительно)
```

Если клиент заплатил больше накопленного выполнения, превышение показывается как аванс, а не как отрицательная дебиторка.

На Overview показатели `Выполнено`, `Получено`, `Расходы` и `Прибыль` относятся к выбранному периоду.
`Общая дебиторка` считается накопительно на конец выбранного периода.

Верхний KPI `Сумма сделок за период` учитывает только сделки, дата которых попала в выбранный период. В карточке конкретного проекта всегда показывается полная договорная сумма сделки.

Денежные значения хранятся в SQLite в целых копейках (`INTEGER`), а не в `REAL`.

## Финансовое состояние

Финансовое состояние не зависит от операционного статуса `В работе / На паузе / Завершён`.

Используются три группы:

- **Отлично** — сильная экономика;
- **Стабильно** — показатели в допустимом диапазоне;
- **Риск** — есть критический финансовый фактор.

При оценке используются прибыль, рентабельность и отношение дебиторки к накопленному выполнению. В интерфейсе доступна расшифровка причин присвоенного состояния.

## Быстрый запуск

Требуется **Node.js 22+**.

В проекте нет внешних npm-зависимостей.

```bash
git clone https://github.com/evgen007776-cell/bitrix24-project-finance.git
cd bitrix24-project-finance
npm run demo
npm start
```

Открыть:

```text
http://localhost:3000
```

На Windows PowerShell при ограниченной Execution Policy можно использовать:

```powershell
npm.cmd run demo
npm.cmd start
```

## Архитектура

```text
Browser / Bitrix24 iframe
        │
        ├── Vanilla JS SPA
        │     public/
        │
        └── REST API
              Node.js http
                  │
                  └── SQLite
                      WAL mode
```

Почему SQLite:
- одна серверная база для нескольких сотрудников;
- простая локальная проверка задания;
- не требуется отдельный сервер БД;
- WAL позволяет разделять чтения и записи.

При росте нагрузки storage можно заменить на PostgreSQL без изменения основной пользовательской модели.

## Bitrix24

При запуске внутри портала frontend пытается получить текущего пользователя через Bitrix24 JS SDK.
Если SDK недоступен, приложение продолжает работать в standalone-режиме.

Для тестового задания намеренно не сделана обязательная OAuth-авторизация: это позволяет проверяющему запустить приложение без портала, секретов и внешней конфигурации.

Для production-развёртывания следующим шагом были бы:
- серверная OAuth-проверка Bitrix24;
- роли и права доступа;
- синхронизация сотрудников из Bitrix24;
- журнал аудита изменений.
