# Project Finance for Bitrix24

Небольшое веб-приложение для совместного ручного учёта доходов и расходов по проектам. Подходит для размещения как отдельный сервис и для встраивания в Битрикс24 через iframe приложения.

## Что реализовано

- проекты с клиентом, описанием и статусом;
- доходы и расходы по каждому проекту;
- системная статья дохода «Оплата от клиента»;
- системные статьи расходов:
  - внешние программисты;
  - внутренние программисты;
  - расходы на ИИ;
  - аренда сервера;
  - дивиденды;
- ручное добавление новых статей доходов и расходов;
- справочник сотрудников и добавление сотрудников в команду проекта;
- общий сервер и SQLite-БД — несколько сотрудников видят одни и те же данные;
- дашборд по всем проектам;
- по каждому проекту: доход, расход, прибыль, рентабельность;
- попытка определить текущего пользователя через официальный JS SDK Bitrix24 при запуске внутри портала;
- standalone-режим без Bitrix24 для быстрой проверки задания;
- серверная валидация сумм и дат;
- автоматические тесты финансовой формулы и API.

## Финансовые расчёты

```text
Прибыль = Доходы − Расходы
Рентабельность = Прибыль / Доходы × 100%
```

Если доход равен нулю, рентабельность отображается как `0%`, чтобы избежать деления на ноль. Отрицательная прибыль при этом сохраняется и показывается явно.

## Быстрый запуск

Требуется **Node.js 22+**. Внешние npm-зависимости не используются.

```bash
git clone https://github.com/evgen007776-cell/bitrix24-project-finance.git
cd bitrix24-project-finance
npm start
```

Открыть: `http://localhost:3000`

### Демо-данные

```bash
npm run demo
npm start
```

Команда `npm run demo` очищает пользовательские данные локальной БД и создаёт два демонстрационных проекта с операциями и сотрудниками.

### Тесты

```bash
npm test
```

### Docker (опционально)

```bash
docker build -t bitrix-project-finance .
docker run --rm -p 3000:3000 -v project-finance-data:/app/data bitrix-project-finance
```

## Встраивание в Bitrix24

1. Разместить приложение на HTTPS-домене.
2. Создать локальное приложение/placement в Битрикс24 и указать URL сервиса как URL обработчика.
3. Открыть приложение из Битрикс24.

Frontend пытается загрузить официальный Bitrix24 JS SDK и вызвать `user.current`. Если SDK недоступен, приложение продолжает работать в standalone-режиме. Идентификатор текущего пользователя передаётся на backend в поле автора финансовой операции.

Для production-версии я бы добавил OAuth/проверку `auth`-токена на backend и синхронизацию сотрудников непосредственно из `user.get`, но для тестового задания намеренно оставил запуск без секретов и обязательной настройки портала.

## Архитектура

```text
Browser / Bitrix24 iframe
        │
        ├── Vanilla JS SPA (public/)
        │
        └── REST API (Node.js http)
                 │
                 └── SQLite (WAL mode)
```

SQLite включён в WAL-режиме и используется как общий серверный storage. Это лучше `localStorage` для совместной работы: изменения одного сотрудника сразу доступны остальным после обновления данных.

## API

Основные endpoints:

- `GET /api/dashboard`
- `GET|POST /api/projects`
- `GET|PATCH /api/projects/:id`
- `GET|POST /api/categories`
- `GET|POST /api/employees`
- `POST /api/projects/:id/members`
- `DELETE /api/projects/:id/members/:employeeId`
- `POST /api/transactions`
- `PATCH|DELETE /api/transactions/:id`

## Как использовался ИИ

ИИ использовался как ускоритель разработки для:

- декомпозиции требований;
- черновой генерации структуры проекта и интерфейса;
- проверки edge cases финансовой формулы;
- генерации части тест-кейсов;
- ревью SQL-запросов и REST API.

Результат проверялся вручную и автоматическими тестами. В частности, при ревью был обнаружен типичный риск SQL-агрегации: прямой JOIN операций и участников проекта мог бы умножать суммы на количество сотрудников. Финансовые операции и команда поэтому агрегируются независимо, а на этот сценарий добавлен отдельный API-тест.
